## 写作规范

1. **元信息头**：每份文档标题下用一行引用块给出 `文档定位 ｜ 对应版本 ｜ 最后更新`，三项必填；确实不适用时写“不适用”，不留空。
2. **标题层级**：`#` 仅用于文档标题且每文件唯一；`##` 为章节，`###` 为章节内分组；不跳级。
3. **版本号**：统一两位小数写法（如 `07.48`）；版本号只在 `ModVersion.cs` 定义，文档引用该值，不另立来源。
4. **日期**：一律 `YYYY-MM-DD`。
5. **命令与路径**：用反引号包裹（如 `./build.ps1`、`docs/verification/run-all.ps1`），路径分隔用 `/`。
6. **列表与表格**：无序列表用 `-`，有序列表用 `1.`；表格只用于结构化对照，不用于叙述。
7. **标点**：中文正文用全角标点；代码、命令、标识符、版本号用半角。
8. **结论前置**：每节先给判定，再给依据；严格区分“已验证”与“未验证”，不得用计划冒充已实现。
9. **可追溯**：结论处标注依据（提交号、产物哈希、日志时间、检查项数）。
10. **目录**：结构较长的文档（项目记忆、工程手册、长期计划）在元信息头后附目录，目录项须与实际标题一一对应；变更记录按时间倒序，不设目录。

## 变更记录条目格式

- 交付条目：`## 07.48 · 标题`，版本号即唯一标识。
- 非交付条目：`## 工程 · YYYY-MM-DD · 标题`。
- 状态标记统一置于标题末尾括号内：`（待游戏验证）`、`（已验收）`、`（已被替代）`。
- 倒序排列，新条目置顶；正文依次说明：改了什么、依据、验证方式、未覆盖范围。

## 术语表

| 术语 | 含义 |
| --- | --- |
| 基线 | 当前交付的版本号及其产物；项目现状一律以项目记忆为准 |
| 产物 | `MOD_YtxSQ1.dll`；Release 输出与游戏调试包内的副本须哈希一致 |
| 游戏加载目录（文档旧称调试包） | `debug/Mod_YtxSQ1/`，加载与Release相同的DLL；名称指官方加载路径，不代表功能缩水或Debug编译 |
| harness | `docs/verification/` 下的托管检查脚本，用替身对象验证产品源码逻辑 |
| 替身 | 检查脚本内模拟 UnityEngine 与游戏类型的桩对象；检查通过不等于游戏内正确 |
| 门禁 | 交付前的强制校验项，任一项失败即返回退出码 1 |
| 变异测试 | 故意向产品源码植入缺陷，验证对应 harness 确实会失败（`run-mutations.ps1`） |
| 托管检查 | 无需游戏即可运行的检查项，总数由 `run-all.ps1` 汇总 |
| 验收 | 用户在游戏内确认可用；只覆盖当轮范围，不扩大为全部字段或跨存档 |
| 待游戏验证 | 已完成编译与托管检查，但尚无游戏内证据 |
| 产品代码 | `ModProject/ModCode/ModMain/` 下会被编译进产物的源码 |
