- 保留已认可山水宣纸、墨刷、字体及立绘；按用户[标题导航参考](screenshots/header-reference-07-21.png)采用紧凑墨刷标题、有圆形底框的×关闭，以及属性/道具/功法/关系/功能/批量/保存七项导航，不加入考拉系列项。角色页左侧操作对象、右侧内容；底部固定居中署名，动态反馈放相关正文。
- 07.21整体界面已获用户认可，后续在此基线上逐步接入功能；没有明确问题或新需求，不再反复重做视觉骨架。导航是产品入口，开发阶段按业务拆分，两者无需一一对应。
- 总览标题、说明与气运区使用统一浅色底框，与下方属性区的底色、边框及留白协调，避免标题浮在山水背景上而内卡片各自孤立。
- 气运区按[逐项参考](screenshots/fates-reference-07-24.png)采用紧凑题栏、列表底框和逐项横条，已拥有条目右侧预留移除×；不以大块摘要或“共几项·点击查看”代替条目。增删走原生生命周期，需持续通过测试存档核对效果与保存重载。
- 用户明确气运条目只显示当前人物拥有的气运，鼠标悬停显示介绍、移开关闭；不点击跳转说明页面。第四栏是全配置检索，标[先]/[后]/[逆]；“气运列表”显示游戏底图并多选，确定后放入第四栏候选区，点击候选才添加给人物。
- 介绍框紧凑、贴在悬停条目旁，右侧空间不足时换左侧；避免覆盖该条目。高度随内容适配，长介绍在框内滚动，窗口边缘需约束。
- 操作按钮保留底框，清楚表达可点击；用户不需要独立刷新按钮，每次重开重新读取名单及当前人物，打开期间保留属性自动更新。
- 角色页按用户[完整参考图](screenshots/role-reference-complete.png)对齐字段、栏目位置及操作入口，范围包括内容和功能，不限于五栏外观。窄画布以滚动保证文字空间；未接入操作明确标注不可用。
- 正式入口拟为大地图人物信息附近的玉符按钮；位置、原UI层级和冲突需核实。F8是当前入口，快捷键配置、正式自定义UI迁移按实际需要推进。
- 输入编辑时不触发打开快捷键；不抢其他窗口。未加载、目标失效及场景不支持时清楚提示并限制操作。
- 不可用/未实现功能明确标注；普通操作不重复确认。复杂或影响进度的操作说明后果，只有经过验证的能力才宣称可恢复。
- UI通过服务访问数据；只读、持久写入、临时开关分别实现。按需查询，场景/存档变化清理引用，提交前复核目标，关闭及失败完整释放。

阶段按目标独立验收，不预估固定工期；局部认可不代表整阶段完成。

| 阶段 | 主要目标 | 验收重点 |

| 0 环境与技术 | 编译、调试、资源/UI加载和生命周期；核实官方自定义UI工具链 | 构建可追溯，加载/关闭可观察，重进不重复注册 |

| 2 角色 | 核实只读字段，挑选低依赖属性/资源跑通编辑、校验、提交与刷新 | 原UI一致、合法/非法输入、目标失效、测试存档保存重载 |
| 3 物品 | 名称/ID、分类、详情、数量和发放，唯一/任务/堆叠规则单列 | 代表物品入包可用、边界数量、长列表性能与保存重载 |
| 4 成长与功法 | 先资质/修为/道点与基本获取，再学习、熟练度、装备与词条；境界/气运独立研究 | 属性计算、装备效果、特殊依赖及保存重载 |

| 7 战斗 | 逐项研究伤害、冷却、资源等临时辅助开关 | 指定目标和场景、关闭/离场释放、连续战斗不叠加 |

**草稿与刷新。** 默认方案是修改立即显示在界面草稿中，点击保存后应用到游戏并持久保存；不在每次按键时写游戏数据。草稿按存档上下文、人物ID、字段及槽位/当前值或上限保存纯托管值，含原值、目标值和状态；不持有原生单位引用。切人物/切模块不丢草稿，保存统一处理本会话有修改的人物并提示数量。2026-10-03用户变更约定：每次打开清空未应用草稿并重新读取；窗口打开期间切人物/模块保留草稿。已应用但磁盘保存失败的内存状态保留待保存计数，不能冒充回滚。退出世界、切存档或MOD销毁释放草稿。每秒快照刷新不替换正在编辑或已有草稿的字段；其他字段照常更新。保存前重新解析每个目标并核对上下文、存活及原值，外部改动产生冲突时说明具体字段、暂停提交，不能默默覆盖游戏新值。

**数值提交。** 显示的是dynUnitData的计算后value，底层PropertyData通常是基础值；先逐字段确认getter、baseValue setter、加成与钳制，目标值不能直接等同基础值。普通资源优先验证原生DynInt.baseValue设置路径及回读；上限、攻击等计算属性各用明确适配器，禁止随意加固定覆盖补丁或循环试写。上限与当前值成组校验；保存时先上限再当前值，修改上限导致当前值超限时在草稿中明确显示随之调整的当前值，不能隐式只写一半。数字溢出、负值、真实合法范围在原位校验；不强设所有资质上限100。年龄/寿命显示为年，存储为月；改年时保留未显示的月余数并检查乘12溢出。暴击倍数按当前整数百分数规则。姓名须核实名字数组结构与原UI刷新，不能未经验证覆盖成单元素数组。

**模块边界。** BookView只管绑定和交互，新增字段描述/快照ID、编辑会话、候选项查询、写入适配器及保存协调服务；按实际复杂度拆文件并登记csproj，不把反射任意字段写入放到视图。WindowInputScope从单搜索框扩展为本窗口登记的输入框集合，保留所有权及仅拒绝无效焦点的规则；F8已有InputField/TMP编辑保护，新增输入仍需验证中文输入法、粘贴、正常失焦和关闭卸载。

**保存失败。** 先整批预检再开始写入，低依赖字段先完成验证。游戏DataMgr.SaveData(Action<bool>)回调确认成功才清除待保存状态；失败区分“未应用”“已应用但未保存”“部分应用”，保留重试所需状态，不把再次点击当重复加值。重读目标确认应用结果；不宣称游戏原生写入具备事务或万能回滚。境界等事件型写入不靠简单恢复字段冒充撤销。保存游戏整体存档的副作用和回调契约须用测试存档核实。

**验收顺序。** 先验证金花逐项名称/分类/介绍和普通人物回归；再验证每对数字独立输入、三兴趣/三性格只替换所选槽、列表边界及刷新不覆盖；最后在测试存档验证资源/上限/单值/姓名/选择字段、合法与非法输入、失效/冲突、重复保存、失败反馈及保存重载。境界单独核对依赖和重载。未获得测试存档安排时可推进只读诊断、草稿与托管验证，但不在当前实际存档试写。

已同意首批为A1–A3、B1–B2、C1、D1基本获取、E1查询及必要交互；定义和来源保留在[功能范围](TRAINER_FEATURE_SURVEY.md)。范围同意不是API可行性结论，也不授权修改实际存档。

先维持稳定界面和只读服务，逐项核实本机getter/修改入口及依赖，再在测试存档做小规模写入、原UI对照和保存重载。一次性持久修改与持续补丁独立验证。高依赖候选先研究，不自动纳入立即开发。

## 迭代与完成标准

每次一个可独立验收的小目标；步骤、回归选择及记录格式遵循工程手册。状态为未开始、研究中、实现中、待游戏验证、已验收或延期。

编译成功、托管检查通过、产物同步、编辑器加载和游戏验收分别记证据。用户成功反馈仅确认当轮问题；不扩大到未执行的全部字段、跨存档或多分辨率。已验收项从阻塞待办移除，相关回归随新变更执行。

仅方向/范围变化更新本计划，避免复述项目记忆。不因单条反馈推倒认可实现；新的替换决策应有明确问题与证据。
