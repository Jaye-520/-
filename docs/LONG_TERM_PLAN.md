# 长期开发计划

制定/精简：2026-10-02。产品暂名「八荒秘录」，官方工程身份MOD_YtxSQ1。

本文件只维护未来方向与阶段门槛；当前实现和验收见[项目记忆](../PROJECT_MEMORY.md)，具体工程方法见[工程手册](ENGINEERING.md)。计划不表示功能已经实现。

## 产品与设计约定

- 面向用户现有鬼谷八荒MOD工程，模块化、逐步开发：先界面，再按功能组接入。其他游戏版本需要实际验证，不预先承诺兼容。
- 保留已认可山水宣纸、墨刷、字体及立绘；按用户[标题导航参考](screenshots/header-reference-07-21.png)采用紧凑墨刷标题、有圆形底框的×关闭，以及属性/道具/功法/关系/功能/批量/保存七项导航，不加入考拉系列项。角色页左侧操作对象、右侧内容；底部固定居中署名，动态反馈放相关正文。
- 07.21整体界面已获用户认可，后续在此基线上逐步接入功能；没有明确问题或新需求，不再反复重做视觉骨架。导航是产品入口，开发阶段按业务拆分，两者无需一一对应。
- 总览标题、说明与气运区使用统一浅色底框，与下方属性区的底色、边框及留白协调，避免标题浮在山水背景上而内卡片各自孤立。
- 气运区按[逐项参考](screenshots/fates-reference-07-24.png)采用紧凑题栏、列表底框和逐项横条，已拥有条目右侧预留移除×；不以大块摘要或“共几项·点击查看”代替条目。移除须完成依赖研究及测试存档验证后才启用。
- 操作按钮保留底框，清楚表达可点击；用户不需要独立刷新按钮，每次重开重新读取名单及当前人物，打开期间保留属性自动更新。
- 角色页按用户[完整参考图](screenshots/role-reference-complete.png)对齐字段、栏目位置及操作入口，范围包括内容和功能，不限于五栏外观。窄画布以滚动保证文字空间；未接入操作明确标注不可用。
- 正式入口拟为大地图人物信息附近的玉符按钮；位置、原UI层级和冲突需核实。F8是当前入口，快捷键配置、正式自定义UI迁移按实际需要推进。
- 输入编辑时不触发打开快捷键；不抢其他窗口。未加载、目标失效及场景不支持时清楚提示并限制操作。
- 不可用/未实现功能明确标注；普通操作不重复确认。复杂或影响进度的操作说明后果，只有经过验证的能力才宣称可恢复。
- UI通过服务访问数据；只读、持久写入、临时开关分别实现。按需查询，场景/存档变化清理引用，提交前复核目标，关闭及失败完整释放。

## 分阶段路线

阶段按目标独立验收，不预估固定工期；局部认可不代表整阶段完成。

| 阶段 | 主要目标 | 验收重点 |
| --- | --- | --- |
| 0 环境与技术 | 编译、调试、资源/UI加载和生命周期；核实官方自定义UI工具链 | 构建可追溯，加载/关闭可观察，重进不重复注册 |
| 1 界面骨架 | 打磨角色页、七项导航、入口、输入与基础适配 | 原生视觉协调、中文清楚、连续开关；当前分辨率及1920×1080/1366×768按适配变更验证 |
| 2 角色 | 核实只读字段，挑选低依赖属性/资源跑通编辑、校验、提交与刷新 | 原UI一致、合法/非法输入、目标失效、测试存档保存重载 |
| 3 物品 | 名称/ID、分类、详情、数量和发放，唯一/任务/堆叠规则单列 | 代表物品入包可用、边界数量、长列表性能与保存重载 |
| 4 成长与功法 | 先资质/修为/道点与基本获取，再学习、熟练度、装备与词条；境界/气运独立研究 | 属性计算、装备效果、特殊依赖及保存重载 |
| 5 NPC与关系 | 检索/只读，逐步研究数值及双向结构关系 | 双方UI与事件一致，无重复/悬空关联，目标失效 |
| 6 宗门与世界 | 先信息/资源，后职位、探索、移动；时间/任务/事件专项 | 原UI、有效位置、月结算与任务链依赖 |
| 7 战斗 | 逐项研究伤害、冷却、资源等临时辅助开关 | 指定目标和场景、关闭/离场释放、连续战斗不叠加 |
| 8 整合发布 | 搜索/收藏/最近操作、配置、兼容、性能、帮助和干净发布包 | 宣称能力均有证据，安装可复现，范围与限制清楚 |

高依赖功能可延期，不阻塞成熟模块。玉符入口、自定义预制体/AssetBundle、组件注册、快捷键配置和战斗支持不能因写入计划就算已实现。对外发布按用户明确指令执行。

## 范围与推进顺序

### 角色页字段与交互约定

参考图的字段及功能都需对应，不能只复刻布局。具体数据以选中人物的真实数据为准，图片中的人物名和数值只是示例；已实现程度见项目记忆。

| 区域 | 对齐目标 |
| --- | --- |
| 气运 | 先天气运、后天气运、逆天改命、所有气运与气运列表入口；已拥有条目的移除入口 |
| 个人属性 | 左列寿命、心情、健康、精力、性别；右列体力、灵力、念力、幸运、悟性；下方兴趣及姓名 |
| 战斗属性 | 左列攻击、防御、脚力、功法抗性、灵根抗性；右列会心、护心、移速、暴击倍数、抗暴倍数；下方性格及境界 |
| 功法资质 | 刀法、枪法、剑法、拳法、掌法、指法；满修为、满材料入口 |
| 灵根资质 | 火、水、雷、风、土、木灵根；去、来、返入口 |
| 技艺资质 | 炼丹、炼器、风水、画符、药材、矿材；双向好感度输入及执行入口 |

数值和姓名的最终交互是点击字段后输入目标值并修改；用户明确允许延期，优先真实只读数据。性别、兴趣、性格、境界等选择型字段的交互需按真实数据结构核实。参考图“去/来/返”“满材料”等操作仅有文字，具体语义及API需研究，不凭截图猜测。额外属性放补充区，不能挤掉参考字段。持久写入仍须分析依赖并用测试存档验证，不擅自操作实际存档。

已同意首批为A1–A3、B1–B2、C1、D1基本获取、E1查询及必要交互；定义和来源保留在[功能范围](TRAINER_FEATURE_SURVEY.md)。范围同意不是API可行性结论，也不授权修改实际存档。

先维持稳定界面和只读服务，逐项核实本机getter/修改入口及依赖，再在测试存档做小规模写入、原UI对照和保存重载。一次性持久修改与持续补丁独立验证。高依赖候选先研究，不自动纳入立即开发。

## 迭代与完成标准

每次一个可独立验收的小目标；步骤、回归选择及记录格式遵循工程手册。状态为未开始、研究中、实现中、待游戏验证、已验收或延期。

编译成功、托管检查通过、产物同步、编辑器加载和游戏验收分别记证据。用户成功反馈仅确认当轮问题；不扩大到未执行的全部字段、跨存档或多分辨率。已验收项从阻塞待办移除，相关回归随新变更执行。

仅方向/范围变化更新本计划，避免复述项目记忆。不因单条反馈推倒认可实现；新的替换决策应有明确问题与证据。
